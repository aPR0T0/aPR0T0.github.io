## First: verify model applicability and preserve negative findings

Check every entry in `results.json` → `source_hashes` and `analysis_input_hashes` against disk. Separate **acquired**, **executable**, **reference-qualified within scope**, and **correlated to this PCB**. A solver reaching its requested end time is not a qualification pass. ## Priority work and acceptance

1. **Resolve the SN74LVC1G125 reference behavior.** Reproduce the undamped reference with the intended vendor simulator and both exact original macro revisions, and compare the saved local ngspice results. SCEM639 v2 fails the output screen; SCEM579 v1 passes the same bounded typical reference screens but omits complete supply-energy accounting. Preserve both outcomes and do not derive an IC current budget from v1. Explain output extrema, ringing, propagation and edge behavior. Native U123/R125 v2 cases use 33 Ω and assumed loading; damping in that network does not prove the vendor reference is sound. Keep its curves conditional until the discrepancy is closed. Qualify the DPW package separately; other-package IBIS parameters are not interchangeable. Then exercise U100/U121/U122/U123 startup, enable and partial-power states with actual source/receiver models and supplied operating limits.
2. **Complete the DDR channel.** Retain the ISSI DM input adapter's source/sign/table tests. Obtain exact RK3566 driver and package data, approved stackup/loss parameters, via/plane/coupling extraction and configured drive/ODT/mode registers. Include DQ, DM, DQS, clock and commands at both DRAMs for read and write. The isolated 0–7 ns DM pulse is not a boot trace or DQS timing margin. Treat the IBIS 110 °C and 1.45 V corner labels as characterization inputs, not approved board operating points. Close with vendor-simulator correlation and source-based eyes/setup/hold/overshoot criteria plus actual training/stress evidence.
3. **Resolve translator power order.** The LSF0102 three-MOSFET model is an explicitly different-part proxy, used with native external resistors. Its back-bias values depend strongly on assumed residual load. Obtain exact PCA9306DQER behavior and DQE parasitics, plus the actual MCU-board CAM_1V8 regulator's discharge/sink/off-state behavior, attached device leakage and capacitance. Test every power-order combination. Select enable, bleed or isolation changes only from the actual voltage/current limits; proxy sensitivity values do not prescribe a resistor.
4. **Qualify installed ferrites under operation.** The new BLM18AG601SN1, BLM18PG121SN1 and BLM21PG601SN1 RF models are for 1 MHz–3 GHz, 25 °C, small signals and zero DC bias. The 50 Ω fixture is not the PCB. Obtain bias/current/temperature dependence, actual source and receiving impedances, capacitor bias/ESR/ESL and loop/return parasitics. Keep published DCR/rating limits separate from RF-fit coefficients. In particular, do not use the BLM21 RF model's 0.17 Ω DC extrapolation as a part rating or silently substitute it for the retained 0.14 Ω maximum. Resolve speaker 1.4 A vs 2 A annotation and camera/codec 0.38 Ω max-DCR findings using exact source evidence.
5. **Obtain the main power/boot models.** TPS566242's exact PSpice model is acquired but remains encrypted and unexecuted here. Run its unchanged reference in a compatible environment or obtain an authorized open model. Resolve RK809-5 OTP/defaults and the fitted TCS4525 revision before writing controller/enable/DVS behavior. The new RESETn RC experiment includes both capacitors, but uses assumed sink resistance, release command and threshold. Replace those assumptions with qualified PMIC/SoC behavior, record actual receiving-pin crossings, and separate requested release from simulated/measured release and downstream activity. Preserve the original four failed campaign cases.
6. **Close load, thermal and remaining functional gaps.** Obtain per-mode SoC/DRAM/Wi-Fi/ToF/display/camera/codec/amplifier loads without double counting downstream branches. Exact codec/amplifier archives or IBIS files are not full functional or thermal models. Identify the actual eMMC and crystal ordering codes. Establish complete losses, mounted-board heat spreading, enclosure/airflow and temperature correlation before making full-board thermal claims. Keep boot and EMC measurement gates open.
