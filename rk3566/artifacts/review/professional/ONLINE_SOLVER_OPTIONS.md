# Online solver options for RK3566 SBC Rev4

Reviewed **14 September 2026** using vendor documentation, product pages, and published access terms. This is a capability and access review; no account was created, design uploaded, subscription purchased, or simulation run as part of this review.

PCB source: `3ba4da7036173e31941ea22b041d1a2a3433c2bcdedccf1a75b1f52b31ce2807`.

**Recommended division of work:** use a supported regulator model for U7 electrical behavior, a conjugate heat-transfer solver for board/enclosure cooling, and a full-wave PCB/system solver for high-frequency EMI. SimScale is a credible browser thermal option. Ansys HFSS/SIwave with Icepak, or Cadence Clarity/Sigrity/Celsius, covers the broader EM/electrothermal workflow. This is an engineering recommendation based on documented scope, not a benchmark establishing which vendor is universally fastest or most accurate.

## Privacy, access and cost findings

- **SimScale:** Community permits only public projects. Other users can access, copy and download public CAD/results. This is unsuitable for an unpublished board unless public disclosure is intended. Private projects are available on paid plans. The current pricing page lists a limited free allowance, rather than unlimited unrestricted free engineering analysis. [Project visibility](https://www.simscale.com/docs/platform/collaboration/), [current plans](https://www.simscale.com/product/pricing/)
- **Ansys:** Cloud access is authenticated and licensed. The separately documented Gateway powered by AWS route uses the customer's AWS account and needs an AWS Marketplace subscription, an Ansys ID and administrator setup. Its nominal free trial still charges AWS infrastructure; platform fees can begin automatically afterward. The old Gateway product URL currently redirects to the broader cloud page, while current marketing emphasizes Cloud Burst Compute. Confirm the available deployment and HFSS/Icepak entitlements with the existing account; do not assume Gateway and Burst have interchangeable billing or setup. No public-project-only requirement was found in the reviewed Ansys documentation, but tenant, storage-region and support-access terms were not independently audited. [Gateway setup requirements](https://ansyshelp.ansys.com/public/Views/Secured/CSP/v000/en/pdf/Ansys_Gateway_powered_by_AWS_Administration_Guide.pdf), [Gateway billing](https://ansyshelp.ansys.com/public/Views/Secured/CSP/v000/en/gateway_gs/gs/fees_and_billing.html), [current cloud delivery](https://www.ansys.com/products/cloud)
- **Cadence:** OnCloud documentation describes customer-data segregation, encryption in transit/at rest, and SSO/MFA/role-based access. This is not evidence that every account has identical retention or region settings. Published trial terms describe 8 hours or 30 days, whichever comes first, with different allowances for some CFD roles, payment information required, and automatic paid conversion. Reconfirm the exact role, token/core accounting and renewal at checkout; this review did not enter checkout. The pricing page is JavaScript-dependent, and the trial wording was available through the indexed primary vendor page. [Security controls](https://www.cadence.com/en_US/home/resources/datasheets/cadence-oncloud-security-ds.html), [published trial terms](https://shop.cadence.com/Ecom/all-products)

## What AI can accelerate

SimScale's documented AI training workflow requires an enabled organization license and **at least 20 simulation runs** from a supported analysis type. Conjugate heat transfer is supported; model-error and validation-loss review is explicitly required. Physics AI is therefore useful for exploring variants **after** a representative, verified solver dataset exists. The existing behavioral rail sweep is not a CFD training dataset. [AI training documentation](https://www.simscale.com/docs/ai-model-training/)

SimScale recommends validating final candidates with its full physics solvers; prediction quality depends on coverage of the intended design space. “Instant predictions” must not be interpreted as instant measurement-equivalent results for this previously unmodeled PCB. For this first board qualification study, setup automation and parallel independent cases are more immediately useful than training a new surrogate. The latter sentence is engineering judgment, not a measured speed comparison. [Physics AI workflow](https://www.simscale.com/product/physics-ai/), [documented accuracy limits](https://www.simscale.com/technology/simulation-ai-engine/)

## Inputs still required for credible Rev4 results

These requirements follow from the actual local model gaps and the physics being requested; buying cloud compute does not supply them.

| Input | What must be established |
|---|---|
| **Component heat generation** | RK3566, RK809-5, DDR, eMMC, interfaces and regulators need per-component loss estimates or measured/validated power versus operating state. Converter output power is delivered to loads; assigning it again as converter heat double-counts energy. Unknown heat sources remain unknown or explicitly bounded assumptions. |
| **Thermal construction** | Package/compact thermal models, PCB layer conductivities and heat capacities, vias/copper fractions, solder/contact resistances, heatsink/TIM, enclosure, board orientation, ambient and airflow/fan curves. Junction temperature and outer-package temperature must remain distinct. |
| **Fabricator stackup** | Confirmed laminate/resin system, layer/dielectric thicknesses, copper thickness/roughness, frequency-dependent permittivity/loss and thermal properties. The existing proposed FR4/35 µm construction is not a fabricator-qualified material definition. |
| **Electrical excitation** | Supported U7 controller behavior, input/output capacitor ESR/ESL, inductor loss/saturation behavior, source/return network, load transitions and actual switching edges. For DDR/other high-speed nets, obtain appropriate driver/receiver/package models and traffic assumptions. |
| **EM environment** | Actual copper and zone connectivity, connector/cable terminations, enclosure/shielding, reference planes, ports and the observation/test arrangement. A local B-field contribution or DC Joule-heating result does not establish radiated-emissions compliance. |
| **Import fidelity** | Prove units, coordinates, net identities, layer order, filled zones and via spans survive the chosen ECAD/MCAD import. Native KiCad support for every candidate was not verified in this review; do not treat a mechanical STEP model as an electrically complete PCB. |
| **Boot validation** | Firmware, exact PMIC variant/OTP, DDR configuration and device/board evidence remain separate requirements. None of these cooling/field workflows supplies complete RK3566 Boot ROM/DDR/Linux execution from a BOM. |

The thermal input requirement is directly reflected in both the [SimScale heat-source documentation](https://www.simscale.com/docs/simulation-setup/advanced-concepts/power-sources/) and [Icepak's stated IC-power/board-loss inputs](https://ansys.synopsys.com/products/electronics/ansys-icepak). Local scope and outstanding electrical evidence are recorded in `simulation/data/electrical-audit.json` and `simulation/TIME_DOMAIN_EM_ANALYSIS.md`.

## Practical execution order

1. Preserve the latest board source hash and obtain the exact regulator-model comparison already being pursued through TI. Retain actual saved component values and separately label any vendor-proposed replacements.
2. Reuse an existing authorized private solver account if it includes the needed physics. Otherwise shortlist **SimScale Professional for board cooling** and **Ansys HFSS/SIwave/Icepak or Cadence OnCloud for the full EM/electrothermal workflow**. Account availability and import effort may dominate the time to the first defensible result.
3. Validate a small U7/return-path extraction first: connectivity, one reference operating point, mesh/time-step convergence and loss balance. Expand to the board and enclosure only after that import is trustworthy.
4. Run startup, steady operation, load changes and adverse conditions using separate electrical and thermal time scales. Preserve failed corners. Report solver settings, assumptions, residual/convergence checks, peak locations and unknown components alongside plots/video.
5. Publish actual solver exports in the local web app with source identity, named quantities, units and clearly stated scope. Mark unrun cloud cases as unrun. Numerical convergence improves confidence in the mathematical solution; hardware temperature, boot and EMC evidence still require correlation with the real board.

No defensible total run time, cost or “most accurate” ranking can be established from marketing claims alone. Compare a common imported geometry, excitations, mesh/convergence target and requested outputs before selecting compute size or making a speed claim.
